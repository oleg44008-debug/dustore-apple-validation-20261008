# DUSTORE LAUNCHER V для macOS

Версия 5.4.1, 9 октября 2026: общая тема Obsidian для Free и Prime, лавандовое выделение, яркие кнопки действий, адаптивная библиотека, редактор доступных параметров eX, мягкие переходы разделов и карточек. Prime сохраняет отдельную редакцию сборки `-p:DustoreEdition=Prime`; Free — `-p:DustoreEdition=Free`. Вход в магазин не меняет редакцию. Режим «Уменьшить движение» доступен в обеих версиях и учитывает системную настройку macOS.

Пакеты `.app.zip`, собранные на Windows, проходят структурную проверку Mach-O, архитектуры, встроенных зависимостей, минимальной macOS и исходного логотипа. Это **не** проверка запуска на Mac, подписи Apple или Gatekeeper. Новые DMG на Windows не создаются. Для окончательной проверки и подписанного пакета требуется macOS и `packaging/verify_macos.py`.

ULTRA сохраняет разрешение и качество изображения. Для Wine можно выбрать маршрут по игре: Auto использует DXMT для Unity на Apple Silicon с macOS 14+, совместимый маршрут сохраняет Wine/DXVK, Metal можно выбрать явно для Direct3D 10/11. В окружении игрового процесса очищаются настройки другого рендерера; переменные самого лаунчера не меняются. Прямой Wine-процесс получает application resource policy через системный `taskpolicy`, кэш шейдеров и собственные журналы. Лаунчер минимизируется, завершает движение интерфейса и перестаёт опрашивать спокойный скрытый WebKit. Файлы `Performance/*.json` фиксируют применённый маршрут и параметры; они не являются замером FPS. Универсальный прирост производительности не гарантируется: необходимы измерения конкретной игры на Mac.

eX показывает фактические этапы и реальное ожидание Free. Отмена до сохранения не списывает перенос; ошибка новой операции сохраняет уже готовую игру. Закрытие окна при работающей игре сохраняет панель выхода и возврата. Полный выход отдельно запрашивает завершение игр и текущей операции.

Это отдельное настольное приложение Avalonia, собранное для macOS. Windows EXE не используется как лаунчер на Mac. Движок переноса игр общий с Windows-версией.

## Установка

1. В меню Apple → «Об этом Mac» проверьте процессор. Для Apple M1/M2/M3/M4 и следующих поколений нужен архив `osx-arm64`; для Intel — `osx-x64`.
2. Откройте `DUSTORE-LAUNCHER-V-5.4.1-osx-arm64.dmg` или `…-osx-x64.dmg` и перетащите **DUSTORE LAUNCHER V.app** в ярлык **Applications / Программы** внутри образа. Архивы Prime имеют `PRIME` в имени.
3. Откройте лаунчер из «Программ». DMG сохраняет macOS metadata подписи при передаче через другие ОС.

Альтернативный формат — `…app.zip`: передавайте на Mac сам ZIP и распаковывайте средствами macOS. Распаковка `.app` на Windows может потерять metadata подписи.

.NET устанавливать не нужно: соответствующий runtime и библиотеки интерфейса включены в каждый архив. Внутри `.app` лежит Mach-O приложение для выбранного процессора. Значок создан из исходного логотипа DUSTORE с сохранением пропорций и прозрачности.

Целевой минимум — macOS 10.15 Catalina для Intel и macOS 11 Big Sur для Apple Silicon. Сборка проверяет, что встроенные нативные компоненты не требуют более новой ОС. Это аудит ограничений бинарных файлов; старые версии не становятся проверенными только благодаря этому минимуму. CI проверяет реальный запуск на доступных Mac runner, а не на каждой исторической версии macOS.

Интерфейс выбирает Metal, затем OpenGL и программный рендеринг, если более быстрый путь недоступен. Фактический графический путь зависит от Mac и его драйверов; настройки графики самой игры задаются отдельно.

Тестовые сборки имеют ad-hoc подпись, без Developer ID и нотариализации Apple. Если macOS показывает предупреждение о неизвестном разработчике, после попытки запуска откройте **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть** и подтвердите именно этот лаунчер. Не нужно отключать Gatekeeper целиком. [Официальная инструкция Apple](https://support.apple.com/en-us/102445).

## Библиотека и eX

Добавьте собственную сборку игры через интерфейс библиотеки. Для запуска нужна macOS-сборка `.app` либо другой действительно поддерживаемый формат; Windows EXE сам по себе не становится приложением macOS. eX анализирует выбранную сборку и показывает доступный маршрут, ограничения движка и необходимость дополнительных компонентов. Созданный пакет проверяйте на целевой системе.

Локальная библиотека хранится в `~/Library/Application Support/DUSTORE Launcher V`, отдельно от Windows-версии. Переменная `DUSTOREV_PROFILE_DIRECTORY` задаёт отдельный профиль для разработчика и CI; обычному пользователю она не нужна. Добавление игры и создание нового пакета сохраняют исходный файл.

Поиск — ⌘F, добавление — ⌘O, библиотека/eX/магазин — ⌘1/⌘2/⌘3, настройки — ⌘,. Стрелки выбирают карточку, Enter запускает выбранную игру или открывает её в eX. PageUp/PageDown переключают страницы по 60 игр. ⌃⌘F и F11 включают полноэкранный режим, Escape выходит из него. В коротком окне главный блок сжимается; названия первой строки игр остаются видимыми. Папки и файлы можно перетащить в окно.

ULTRA и установка дополнительных графических компонентов показывают текущий этап и поддерживают отмену. Переключение параметров применяется к следующему запуску. Wine-сессия хранит фактический процесс, runtime и prefix, поэтому закрытие игры использует маршрут, с которым она была запущена. Журналы stdout/stderr ограничены двумя мегабайтами каждый; поток продолжает читаться, чтобы шумная игра не блокировалась. При сворачивании откладываются декодирование обложек и импорт завершённых загрузок; после восстановления работа продолжается.

## Сборка

Используются .NET 8 и Avalonia 11.3.21. Для локального проекта путь к pure Core задаётся автоматически либо параметром `--converter-core`. В изолированном validation checkout можно передать точный Core DLL через `--converter-assembly`; проектные исходники Core для этого не требуются.

```sh
python3 packaging/build_macos.py --rid osx-arm64 --output artifacts/osx-arm64
python3 packaging/build_macos.py --rid osx-x64 --output artifacts/osx-x64
python3 packaging/build_macos.py --edition prime --rid osx-arm64 --converter-assembly ../Dependencies/DustoreX.AutoConverter.Core.dll --output artifacts/prime-arm64
```

На macOS скрипт подписывает вложенные файлы Avalonia/.NET, каждый нативный компонент, затем весь `.app`, проверяет подпись и создаёт ZIP через `ditto` с сохранением macOS metadata. На Windows он может создать структурно проверенный архив для Mac с сохранённым Unix-битом запуска, но без macOS-подписи и проверки реального старта. Для выдачи пользователю используются архивы, собранные и проверенные Mac CI.

Для повторного кодирования значка нужен Pillow; исходный PNG должен иметь закреплённую контрольную сумму. Готовый `.icns` уже входит в проект, поэтому при обычной сборке Pillow не требуется.

```sh
python3 packaging/make_icon.py Assets/dustore-logo-original.png packaging/DustoreLauncherV.icns
```

## Проверка на настоящем Mac

```sh
python3 packaging/verify_macos.py \
  --archive artifacts/osx-arm64/DUSTORE-LAUNCHER-V-5.4.1-osx-arm64.app.zip \
  --rid osx-arm64 --output artifacts/verification --normal-launch --ui-smoke
```

Verifier извлекает архив в новый временный каталог, проверяет архитектуру, исполняемые права, целостность `.app`, нативные зависимости и подпись. Затем запускает именно включённый apphost из посторонней рабочей папки, с отдельным профилем. `--smoke-input` позволяет дополнительно анализировать выбранный игровой ZIP и проверить импорт в собственный каталог; игра не запускается.

`--normal-launch` дополнительно открывает `.app` через LaunchServices командой `open -n -W` с обычными аргументами, стандартным профилем и стандартным выводом Finder. Независимый наблюдатель связывает процесс с точным bundle, проверяет успешную загрузку библиотеки и наблюдает настоящее экранное окно не менее 10 секунд. Диагностические флаги лаунчера при этом не используются; завершение проверки касается только её собственного экземпляра.

Mac CI также создаёт DMG, монтирует его только для чтения, копирует приложение в свой тестовый каталог через `ditto`, повторно проверяет подпись и обычный запуск установленной копии. После проверки отсоединяется только этот образ. Создание DMG не меняет подпись приложения и не выполняет нотариализацию Apple.

При обычном запуске диагностический отчёт находится в `~/Library/Logs/DUSTORE Launcher V/last-startup.json`, текстовый журнал — рядом в `startup.log`. Они помогают отличить сбой инициализации от отказа ОС запустить приложение.

`--ui-smoke` открывает собственное окно Avalonia на Mac runner, создаёт изображения действительно инициализированных разделов библиотеки, eX и настроек и завершает приложение. `--offline-ui-smoke` дополнительно проверяет маршрутизированные клавиатурные события, имена automation peers, короткое окно, редактор eX, повторный импорт после ошибки/отмены и каталог из 2000 созданных записей без обращения к магазину. Обычные проверки библиотеки используют recording adapter. Дополнительно оба GUI режима на Mac компилируют отдельный собственный Swift/AppKit fixture: виртуальная игровая поверхность 5000×3000, размер окна через документированный Godot argument contract, настоящий LaunchServices/PID lifetime, отдельная панель выхода, минимизация/возврат и повторное открытие в native fullscreen Space. JSON отделяет этот собственный fixture от проверки стороннего Godot runtime; PNG показывают все углы и панель. Ручная проверка VoiceOver, все сторонние игры и игровой FPS этим не подтверждаются. Сервисная проверка запускает только собственные тестовые дочерние процессы, проверяя lifetime, остановку, cancellation/deadline и ограниченные журналы. Ограничение времени касается процессов, запущенных verifier.

Unity и Godot впервые запускаются в окне, подходящем рабочей области текущего экрана, с сохранением пропорций. Явно выбранные «Весь экран» и «Как в игре» сохраняются. Другим движкам не передаются выдуманные аргументы. Нативные `.app` наблюдаются через AppKit по точному пути и PID; закрытие доступно только для подтверждённой сессии. Панель «Лаунчер / Выйти из игры» остаётся отдельной от минимизируемого лаунчера; normal quit и принудительное завершение — разные действия. Escape/⌘W работают, когда фокус находится в этой панели; ⌘Tab возвращает к лаунчеру. Глобальных перехватчиков клавиатуры и запроса Accessibility permission для изменения чужих окон нет. Native menu «Файл / Вид / Игра» открывает настоящие действия библиотеки, настроек и подтверждённой игровой сессии.

Отдельный публичный validation checkout содержит `launcher-mac/`, `ios/` и закреплённую DLL Core в `Dependencies/`. Его workflow собирает Free и Prime на ARM и Intel, сохраняет архивы и фактические JSON/PNG-отчёты. Он не изменяет исходные внешние проекты. Дополнительная диагностика `--wine-smoke` устанавливает закреплённые Wine/DXVK/DXMT и выполняет созданный Windows command fixture через пакет и прямую сессию; она не создаёт Direct3D device и не измеряет FPS игры.

Схема упаковки и требования к JIT-подписи основаны на [документации Avalonia](https://docs.avaloniaui.net/docs/deployment/macos). Раздельные runtime identifiers описаны в [документации .NET](https://learn.microsoft.com/en-us/dotnet/core/deploying/macos); архитектуры Mac runner — в [документации GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
